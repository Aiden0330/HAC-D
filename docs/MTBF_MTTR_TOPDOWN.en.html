Top-down: from the availability target to hardware MTBF and mechanism MTTR

Basis：job operational availability A_op (running-time share of the 30-day window), target the scenario default 98.5 %; main case the A3 · CloudMatrix384 topology with the six default mechanisms at the built-in 10k / 100k / 200k / 500k NPUs (A2 and Atlas 950 requirements in section 2). The design must hold with derated parameters (coverage −5 pt, success −8 pt, times ×1.5), so requirements are computed on the derated design. FIT are the reference catalog’s priors (assumed) converted to hardware units under the CloudMatrix384 geometry. Every number is computed on the engine by scripts/mtbf-mttr-topdown.ts; the formula matches the engine’s running fraction term by term (difference < 10⁻⁹).

1. The top-down formula

① One event class (classic):
A = MTBF / (MTBF + MTTR)
② Job level: each event class k keeps its own MTBFₖ and MTTRₖ (event classes are never merged into one MTBF); silent-corruption episodes enter as φ_SDC:
A_op = (1 − φ_SDC) / (1 + MTTR_hw/MTBF_hw + Σₖ MTTRₖ/MTBFₖ)
③ MTBF level: the job-level MTBF of hardware interruptions combines the MTBF of each hardware unit with its count nᵤ(N):
1 / MTBF_hw = Σᵤ nᵤ(N) / MTBFᵤ , MTBFᵤ = 10⁹ / FITᵤ [h]
④ MTTR level: the mean pause per hardware interruption, rate-weighted over the classes, each through the mechanism chain (netfail → replay → elastic → process → global recovery):
MTTR_hw = Σᵢ (λᵢ/λ_hw) · Σ_path P(path) · T(path) ; T(global) = t_det + Σ t_fail + t_auto + (1 − s)·t_manual ; t_det = c·t_fast + (1 − c)·t_timeout
⑤ Requirement (MTBF_hw in hours, MTTR in seconds):
MTTR_hw / MTBF_hw ≤ B , B = 3600·((1 − φ_SDC)/A* − 1) − F , F = Σₖ 3600·MTTRₖ/MTBFₖ [s/h]
⇒ MTBF_hw ≥ MTTR_hw / B or MTTR_hw ≤ B · MTBF_hw

The table checks formula ② on the 500,000-NPU design today (derated): the ratios 3600·MTTRₖ/MTBFₖ of the event classes add up and, with (1 − φ), give exactly the engine’s A_op. MTBFᵤ = 10⁹ / FITᵤ hours ÷ 8,760; FITᵤ = the interruption FIT of all fault classes on the unit (business-impact 口径). Share = nᵤ·FITᵤ / Σ. Job-level result of the 500k recommended split: MTBF_hw 0.707 h (42.4 min) (today 0.591 h (35.5 min)).

Using it as hardware requirements: take “minimum MTBF (years / unit)” as the unit’s acceptance value; when a unit carries several fault classes, split it to the suppliers by class FIT (e.g. a cabinet: power and cooling). At 500k the hardware-only plan needs NPUs at 99.5 years, cabinets at 95.2 and job-level services at 2,910 (today 68.1 / 13.4 / 210); the recommended split keeps the NPU as it is and asks only cabinets 23.0 years, job-level services 738 and nodes 29.1 — the rest is carried by MTTR (section 4).

Each line is rate-weighted; the lines add up exactly to MTTR_hw (every fault class is checked against the engine’s mean pause). When the elastic rung succeeds the job pauses only for the sync while the domain recovers in the background (that capacity loss counts in goodput, not in the A_op pause). Applicability comes from the reference catalog’s per-event flags (replay only acts on replayable events, etc.).

Summary (A3 · CloudMatrix384, A_op ≥ 98.5 %): the requirement is MTTR_hw / MTBF_hw ≤ B ≈ 46–55 seconds per hour. 10k and 100k work with the six default mechanisms (MTTR 104 s, MTBF_hw 29.7 / 2.96 h); 200k only needs the automatic attempt cut to 60 s, which brings MTTR_hw to 75.1 s, with no hardware change; 500k needs MTBF_hw 0.707 h (42.4 min) and MTTR_hw 35.8 s (derated): on the hardware side cabinets ≥ 23.0 years, job-level services ≥ 738, nodes ≥ 29.1; on the mechanism side detection ≈ 1 s (D-HARD), network failover (R-NETFAIL), automatic attempt 60 s, manual repair 30 min.
Notes: ① the split between MTBF and MTTR is the least-effort combination (v4 optimal); the effort scores are assumptions and other scores give another split (e.g. at 200k hardware alone also works, effort 5.19 against 3 for the lever). ② Mechanism parameters are the library values, not solved minimum values; the document gives the values at which the requirement is met and the MTTR each carries. ③ Isolation, detected silent corruption and the other event classes keep their own MTBF and MTTR and are not merged into MTBF_hw; they set F in the budget B. ④ Failure rates are the reference catalog’s priors (assumed) and must be replaced by measurements of the cluster.
