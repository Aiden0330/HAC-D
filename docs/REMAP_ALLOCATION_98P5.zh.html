98.5 % 运行可用率目标下的可靠性分配：仅用 ReMAP 原有机制（1 万 / 10 万 / 20 万 / 50 万卡）

口径：A_op = 作业窗口（30 天）内的运行时间占比，目标 ≥ 98.5 %（不可用度预算 1.5 pt）；对象为 54 条事件的参考审核目录（中断 / 亚健康 / 静默 FIT 3333.3 / 69.0 / 48.3 每卡·小时），基线恢复 12.5 s 发现 + 180 s 自动尝试 @ 99 % + 2 h 人工（R̄ = 264.5 s）。候选机制仅取 ReMAP 原有的 12 项：参与规划与归因的是有参数变换的 8 项（D-HARD、D-SLOW、D-SDC、R-SDC、R-REPLAY、R-PROCESS、R-ELASTIC、C-FAST），R-CKPT / R-MANUAL 为基线恢复本身，H-PROTECT / H-RELIABILITY 无增量参数（硬件改进由硬件预算单独给出）；HAC-D 自带的 v3.2 七项与 2026-10-14 新增的 16 项均不参与。机制参数为参考目录的目标值（先验），规划器按覆盖率 −5 pt、成功率 −8 pt、时间 ×1.5 降额后仍须达标；校核用 200 个窗口的账本仿真对 90 % 置信度（Wilson 区间）。

5. 结论：各规模的薄弱环节与最重要的机制

1 万卡：基线已达标（99.75 %）

  • 无需机制；硬件余量 × 6.2，恢复余量 × 6.0（R̄ 可放宽到 1597 s）；200 个窗口全部 ≥ 98.5 %（5 % 分位 99.49 %）。
  • 薄弱环节（方案后残余）：NPU 芯片与内存 46 %，存储 / 软件 / 未归因 16 %。
  • 最重要的 ReMAP 机制（Shapley）：R-ELASTIC +0.08，R-PROCESS +0.04，R-REPLAY +0.03。

10 万卡：缺 0.95 pt，ReMAP 机制可以补足

  • R-ELASTIC（工作量 5）→ 99.07 %（降额 98.84 %），P(窗口 ≥ 98.5 %) = 98.5 %，supported；方案后硬件余量 × 1.66。更省力的组合（R-REPLAY 名义 98.37 % / 降额 98.29 %；R-PROCESS 名义 98.59 % / 降额 98.24 %）至少有一项不达标。
  • 薄弱环节（方案后残余）：存储 / 软件 / 未归因 42 %，机房设施 31 %；基线时 NPU 芯片与内存 46 %，存储 / 软件 / 未归因 16 %。
  • 最重要的 ReMAP 机制（Shapley）：R-ELASTIC +0.76，R-PROCESS +0.43，R-REPLAY +0.33。

20 万卡：缺 3.28 pt，ReMAP 原有机制不够

  • 8 项全部启用也只到 98.36 %；价值最高的集 D-HARD + D-SDC + R-SDC + R-REPLAY + R-PROCESS + R-ELASTIC（工作量 21）98.36 % / 降额 98.11 %，P(窗口 ≥ 目标) 38.5 %。
  • 补足途径：硬件中断率须降到 91 %（× 1.10，各域允许 FIT 见第 4 节），或在机制集之上加恢复杠杆 + 三项同时（99.53 % / 降额 99.30 %，硬件余量 × 3.35）。
  • 薄弱环节（方案后残余）：存储 / 软件 / 未归因 46 %，机房设施 34 %；基线时 NPU 芯片与内存 46 %，存储 / 软件 / 未归因 16 %。
  • 最重要的 ReMAP 机制（Shapley）：R-ELASTIC +1.48，R-PROCESS +0.84，R-REPLAY +0.64。

50 万卡：缺 9.62 pt，ReMAP 原有机制不够

  • 8 项全部启用也只到 95.99 %；价值最高的集 D-HARD + D-SDC + R-SDC + R-REPLAY + R-PROCESS + R-ELASTIC（工作量 21）96.00 % / 降额 95.41 %，P(窗口 ≥ 目标) 0.0 %。
  • 补足途径：硬件中断率须降到 33 %（× 3.06，各域允许 FIT 见第 4 节），或加恢复杠杆 + 三项同时（名义 98.83 % 达标，但降额 98.26 % 不达标）。
  • 薄弱环节（方案后残余）：存储 / 软件 / 未归因 46 %，机房设施 34 %；基线时 NPU 芯片与内存 46 %，存储 / 软件 / 未归因 16 %。
  • 最重要的 ReMAP 机制（Shapley）：R-ELASTIC +3.39，R-PROCESS +1.90，R-REPLAY +1.44。
