口径：主结果为 A_op = 30 天窗口内的运行时间占比，目标 ≥ 98.5 %（预算 1.5 pt），与前几份报告一致；ReMAP 自身的"可用度"是窗口内最终保留的正确进度占比（HAC-D 的正确交付 goodput），第 4 节另给该口径的结果并与 ReMAP 引擎交叉校核。对象为 54 条事件的参考审核目录（与最新仓库 references/expert-review-2026-10-09 一致：中断 / 亚健康 / 静默 FIT 3333.3 / 69.0 / 48.3 每卡·小时），基线恢复 12.5 s 发现 + 180 s 自动尝试 @ 99 % + 2 h 人工（R̄ 264.5 s），τ 300 s、δ 4 s。候选机制 = 最新 ReMAP（github.com/lzq0927/remap，commit eaacb05，2026-10-15）的全部机制：原有 12 项中有参数变换的 8 项（D-HARD、D-SLOW、D-SDC、R-SDC、R-REPLAY、R-PROCESS、R-ELASTIC、C-FAST；R-CKPT / R-MANUAL 为基线本身，H-PROTECT / H-RELIABILITY 无增量参数）+ 扩展 16 项中的 15 项（I-CONTAIN 为支撑能力）。扩展参数取 ReMAP 的显式情景 extensionScenario()：适用 100 %（FP8 / FP4 各占 CORE 静默风险的 50 %）、成功 95 %、失败尝试 0 s、开销 0（ABFT 0.1 %），机制目标值同审核（第 3 节表）；ReMAP 引擎逐事件抽样适用与成功，HAC-D 按期望值折入参数（启动阶段按 95 % 适用、异步阻塞 4 × 5 % + 1 × 95 % = 1.15 s、人工概率 95 % × 0.1 % + 5 % × 1 %）。规划器按覆盖率 / 适用比例 −5 pt、成功率 −8 pt、时间 ×1.5 降额后仍须达标；23 项候选超过精确枚举上限（10 项），改为贪心逐步加入（每步加入单位工作量名义增益最大者），Shapley 置换抽样 300 次（95 % 半宽 ≤ ± 0.25 pt），校核 400 个窗口（Wilson 区间）。已知语义差别：FP8 / FP4 / 网络静默检测 ReMAP 取最大值、HAC-D 在残余漏检上复合；开销连乘 vs 求和（0.1 % 量级）。

6. 结论：各规模的薄弱环节与最重要的机制

规模 · 判定结论（A_op 口径）薄弱环节：方案后残余（基线时）最重要的机制（Shapley，pt）ReMAP 口径（正确交付 ≥ 98.5 %）
1 万卡：基线已达标（99.75 %）无需机制；硬件余量 × 6.2，恢复余量 × 6.0（R̄ 可放宽到 1597 s）；400 个窗口全部 ≥ 98.5 %（5 % 分位 99.49 %）。NPU 芯片与内存 46 %，存储 / 软件 / 未归因 16 %原有 R-ELASTIC +0.07，R-PROCESS +0.03；扩展 D-RECOVERY-CLASSIFY +0.03，R-LINK-LOCAL +0.01基线 93.3 %，D-SDC + C-ASYNC + R-REPLAY → 99.09 % / 降额 98.62 %。
10 万卡：缺 0.95 pt，ReMAP 最新机制集可以补足R-REPLAY + R-PROCESS（工作量 5）→ 98.86 %（降额 98.64 %），P(窗口 ≥ 98.5 %) = 90.5 %，uncertain；方案后硬件余量 × 1.33。 对照：仅原有机制的精确枚举给出 R-ELASTIC（工作量 5）→ 99.07 % / 降额 98.84 %，同等工作量下更优：23 项候选的贪心规划不保证最优，两者都可行。存储 / 软件 / 未归因 34 %，机房设施 25 %（基线时 NPU 芯片与内存 46 %，存储 / 软件 / 未归因 16 %）原有 R-ELASTIC +0.67，R-PROCESS +0.32；扩展 D-RECOVERY-CLASSIFY +0.26，R-LINK-LOCAL +0.11基线 62.6 %，无可行集，最高 98.43 %（20 项），硬件 × 0.90 可补足。
20 万卡：缺 3.28 pt，ReMAP 最新机制集可以补足R-REPLAY + R-PROCESS + D-RECOVERY-CLASSIFY + D-HARD + R-ELASTIC + C-LOSSLESS + H-CONTROL-CONTINUITY（工作量 20）→ 98.95 %（降额 98.58 %），P(窗口 ≥ 98.5 %) = 99.5 %，supported；方案后硬件余量 × 1.48。 对照：仅原有机制时无可行集（最高 98.36 %）；可行性来自扩展项 D-RECOVERY-CLASSIFY、C-LOSSLESS、H-CONTROL-CONTINUITY（合计 Shapley +0.82 pt）。存储 / 软件 / 未归因 49 %，机房设施 25 %（基线时 NPU 芯片与内存 46 %，存储 / 软件 / 未归因 16 %）原有 R-ELASTIC +1.31，R-PROCESS +0.62；扩展 D-RECOVERY-CLASSIFY +0.51，R-LINK-LOCAL +0.21基线 45.7 %，无可行集，最高 97.35 %（20 项），硬件 × 0.23 可补足。
50 万卡：缺 9.62 pt，ReMAP 最新机制集仍不够23 项全部启用也只到 98.00 %；价值最高的集 12 项（原有 4 + 扩展 8，见第 3 节）（工作量 37）97.98 % / 降额 97.11 %，P(窗口 ≥ 目标) 0.0 %；仅原有机制时最高 95.99 %。 补足途径：硬件中断率须降到 72 %（× 1.40，各域允许 FIT 见第 5 节），或在机制集之上加恢复杠杆 + 三项同时（99.10 % / 降额 98.51 %，硬件余量 × 1.72）；仅 + 自动恢复尝试 180 → 60 s 名义 98.99 % 达标但降额 98.26 % 不达标。存储 / 软件 / 未归因 51 %，机房设施 32 %（基线时 NPU 芯片与内存 46 %，存储 / 软件 / 未归因 16 %）原有 R-ELASTIC +3.05，R-PROCESS +1.40；扩展 D-RECOVERY-CLASSIFY +1.18，R-LINK-LOCAL +0.47基线 25.3 %，无可行集，最高 94.38 %（20 项），硬件改进也不可达（常量损失超预算）。
