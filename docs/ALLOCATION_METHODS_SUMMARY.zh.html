可靠性分配方法：原理、公式与算法

分配 = 把系统级目标（可用率 A*、goodput G*、故障率 λ*）自顶向下拆成每个部件类的允许故障率和每项机制的参数设定值，再自底向上预测、校核、迭代。口径规则：同一事件类、同一分母、同一层级；中断、亚健康、静默错误三类事件不能相加，只能各自进入窗口账本后再合成。公式与 HAC-D 的实现一致（packages/core/src/allocation、study、mechanisms/plan）；三份 AGREE 报告（REMAP_ALLOCATION_98P5_AGREE、MECHANISM_COMPARISON_98P5_AGREE、REMAP_LATEST_ALLOCATION_98P5_AGREE）是它们在 54 条事件目录上的算例。

1. 经典分配方法（串联系统，m 个子系统；λᵢ⁰ 当前合计率，λᵢ* 分配率，kᵢ = λᵢ⁰ / λᵢ* 改进倍数）

方法公式输入适用 / 性质
等分λᵢ* = λ* / m；可靠度形式 Rᵢ = (R*)^{1/m}无无信息时的起点
ARINCλᵢ* = wᵢ λ*，wᵢ = λᵢ⁰ / Σⱼ λⱼ⁰ ⇔ 全部类乘同一倍数 k = Σλ⁰ / λ*各类当前率信任现状比例；HAC-D 默认
AGREERᵢ = 1 − (1 − R*^{nᵢ/N}) / Eᵢ，λᵢ = −ln Rᵢ / tᵢ（nᵢ 模块数，N = Σn，Eᵢ 重要度，tᵢ 工作时间）。可用率形式：ptᵢ* = U_free · nᵢ/Σn，λᵢ* = ptᵢ* · 3600 / (A* p̄ᵢ)，U_free = (1 − A*) − 非域暂停项模块数、重要度、工时比；各类停顿 p̄ᵢ模块多、工时长、重要度低 → 预算多；n、E、t 相同时退化为等分
可改进性加权λᵢ* = wᵢ λ*，wᵢ = Πₖ rᵢₖ / Σⱼ Πₖ rⱼₖ（复杂度、技术水平、工时、环境各 1–10 分，越难改分越高）各类评分置信度参差时；HAC-D 用单一权重（假设值 2，否则 1）
最小努力（Albert）当前率降序 λ₍₁₎ ≥ λ₍₂₎ ≥ …；取最小 k 使 λ̄ = (λ* − Σⱼ₎ₖ λ₍ⱼ₎) / k ≥ λ₍ₖ₊₁₎；前 k 类改到 λ̄，其余不动各类当前率少数类主导时最省力；= AGREE 等权 + "余量类不恶化"的再分配
成本最优min Σ aᵢ (λᵢ⁰/λᵢ)^{bᵢ} s.t. Σλᵢ = λ*，λᵢ^min ≤ λᵢ ≤ λᵢ⁰ → λᵢ = (aᵢ bᵢ (λᵢ⁰)^{bᵢ} / ν)^{1/(bᵢ+1)} 截断到区间，ν 二分成本曲线 a、b，下限有改进成本模型时；预算低于下限之和则不可行
不可用度分解Π Aᵢ = A* → ln Aᵢ = (wᵢ/Σw) ln A*，Uᵢ = 1 − Aᵢ；给 MTTRᵢ 则 λᵢ = Uᵢ / (MTTRᵢ (1 − Uᵢ))，给 λᵢ 则 MTTRᵢ = Uᵢ / (λᵢ (1 − Uᵢ))A*，各类 MTTR 或 λ硬件级可用率；每类只能用 λ 或 MTTR 之一兑现
goodput 预算（Young）M = 3600/(N λ_GPU)，L = √(2δ/M) + R/M，L* = 1 − G*；定 R 解 M*，定 M 解 R* = M (L* − √(2δ/M))；均衡 L_r = ρL*δ、R、λ_GPU训练作业；要求 (τ+δ)/M ≤ 0.1 且 R/M ≤ 0.1
恢复阶段预算budgetᵢ = floorᵢ + (wᵢ − floorᵢ) / Σⱼ(wⱼ − floorⱼ) · (R* − Σ floor)，wᵢ 默认当前阶段时间，检测下限 5 s阶段时间、下限定 λ 压 R 时拆到检测 / 自动 / 人工份额

2. 算法（HAC-D 实现）

A · AGREE 可用率分配与再分配

  1. 固定项 fixed = Σ 非域暂停（亚健康隔离、静默错误即时检出、预测误报）；U_free = (1 − A*) − fixed
  2. ptᵢ* = U_free · nᵢ / Σn；λᵢ* = ptᵢ* · 3600 / (A* · p̄ᵢ)；kᵢ = λᵢ / λᵢ*（> 1 须改进）；允许 FIT = 当前 / kᵢ
  3. 再分配（注水）：over = {kᵢ > 1}；重复：rem = U_free − Σ_{i∉over} ptᵢ；若某 i∈over 的 rem·nᵢ/Σ_over n ≥ ptᵢ 则移出 over；直到稳定 → k′ᵢ（硬件任务）
  4. 复算：各类 λᵢ ← λᵢ / kᵢ，引擎重算 A_op，应回到 A*（算例 98.50 %）

B · 机制组合选择

  1. 精确（≤ 10 候选）：枚举 2ⁿ 组合，取 min Σ 工作量 s.t. V(名义) ≥ 目标 且 V(降额) ≥ 目标；必要机制 = 所有可行组合的交集；Pareto 前沿（工作量–价值）
  2. 贪心（> 10）：每步加入 ΔV / 工作量最大者，直到名义与降额都达标
  3. AGREE 两阶段：① 按类补缺 — score = [Σ_{i∈over} max(0, ptᵢ − max(ptᵢ^new, ptᵢ*)) − Δfixed] / 工作量；② 造余量 — 剩余超预算类无机制可用时按 ΔA_op / 工作量加入作用于已达标类的机制，余量经再分配补给
  4. 降额 DERATE_DEFAULT：覆盖率 / 适用比例 −5 pt，成功率 −8 pt，时间与开销 ×1.5，削减比例 ×0.5；τ、域数为设计量不降额

C · 自底向上预测与校核

  1. 闭式：27 路径恢复链枚举（预测 → 网络容错 → 重执行 → 热替换 → 弹性 → 进程 → 全局）→ 各类 p̄ᵢ → A_op；窗口账本九项 → 正确交付 goodput
  2. 蒙特卡洛：400 个 30 天窗口账本（同一故障流，机制共享历史）→ P(窗口 ≥ 目标)，Wilson 95 % 区间 → supported / uncertain / below（要求 ≥ 90 %）
  3. 归因：Shapley（≤ 12 项精确，否则置换抽样 ± t 半宽）；分配视角用"消除的超预算量"（单独 / 末位移除）
  4. 闭环：实测事件 → Garwood 率区间（hacd rate）→ 回写 FIT、阶段时间、检出率 → 重跑

3. 要点

  • 守恒：Σᵢ ptᵢ + fixed = 1 − A_op，ptᵢ = A_run · λᵢ · p̄ᵢ / 3600。方法只改变"在类之间怎么拆"，总预算相同：ARINC 全部等比，AGREE 按复杂度 / 重要度 / 工时，Albert 只改最差者。
  • 两条杠杆：硬件改 λᵢ（验收限值 FIT = 当前 / k），机制改 p̄ᵢ（梯级把 264.5 s 的全局恢复换成 5–60 s 的就地恢复；检测、人工份额、启动 / 读取阶段的机制作用于所有中断）。有梯级的类拿到余量，经再分配补给没有梯级的 POWER / COOL / MGMT / STORAGE / UNKNOWN。
  • 复杂度与重要度决定 AGREE 的结论：参考目录按每卡·小时归一 → nᵢ 相同 → 等分（10 万卡 13 / 18 类超预算，CORE ×4.2、UNKNOWN ×3.7）；若按物理单元计，机柜级类的预算缩小 256 倍（POWER ×188、STORAGE ×8400）。串联作业里每个硬中断都停作业 → Eᵢ = 1；整窗暴露 → tᵢ = T。
  • 筛选律：无故障上界 G ≤ τ/(τ+δ)，高于最佳组合上界的目标"已证明不可达"；规模律：检测与恢复项 ∝ N，checkpoint 项 ∝ √N，静默污染次数 ∝ N——按将运行的最大 N 分配。
  • 算例（54 条事件目录，A_op ≥ 98.5 %）：基线上限 61k 卡；ReMAP 原有机制的 AGREE 集上限 182k，原有 + 新增 378k，最新 ReMAP 集 373k；20 万卡最新集 99.05 %（工作量 27，P(窗口) 99.8 %）；50 万卡无可行集，AGREE 把硬件任务集中在 UNKNOWN ×2.4 / POWER ×1.31 / STORAGE ×1.05（其余 15 类不动），ARINC 则要求全部 ×1.40。

集群架构如何影响分配，以及分配组件下一步做什么

AGREE 的三个权重（复杂度 n_i、重要度 E_i、工时比 t_i）、各类的集群级事件率和可用的机制都由集群架构决定，而不是由分配方法决定：架构定下每类有多少单元（countRule.per × topology → computeCounts）、一次事件停掉多少卡（blastRadius、ccf.beta、冗余组）、哪些梯级可用（component.mechanisms、弹性域数、热备、平面数）。下表按架构要素列出它改变的分配量、HAC-D 里对应的字段 / 模型和在 98.5 % 算例上的后果；图中按层级给出同样的关系。最后一张表是下一阶段的工作包，细则见 docs/PLAN_V3_8_ALLOCATION_ARCHITECTURE.md。
