98.5 % 目标下的 AGREE 分配：ReMAP 原有机制 · 新增 16 项 · 两者合并（1 万–50 万卡）

口径：A_op = 30 天窗口内运行时间占比，目标 ≥ 98.5 %（预算 1.5 pt），对象为 54 条事件的参考审核目录（中断 / 亚健康 / 静默 FIT 3333.3 / 69.0 / 48.3 每卡·小时），基线恢复 12.5 s 发现 + 180 s 自动尝试 @ 99 % + 2 h 人工（R̄ 264.5 s），τ 300 s、δ 4 s——与此前三份报告相同，不同之处只在分配方法。三个机制族分别作为候选：ReMAP 原有 8 项（库内目标参数）；审核新增 16 项中有变换的 15 项（空缺的集成参数按临时假设填入：适用 100 %、成功 90 %、失败尝试 10 s、FP8 / FP4 风险占比各 1/3，标注 assumed）；两者合并 23 项。 规划器降额（覆盖率 / 适用比例 −5 pt、成功率 −8 pt、时间 ×1.5）、400 个窗口的账本校核（Wilson 区间）同前。

AGREE 分配法（串联系统）：子系统 i 有 n_i 个模块、重要度 E_i = P(系统失效 | i 失效)、工作时间 t_i，R_i = 1 − (1 − R*^{n_i/N}) / E_i，λ_i = −ln R_i / t_i（HAC-D allocation.agree，R* = e^{−λ*T}，一阶后按 Σλ_i = λ* 缩放）。用于可用率目标时同一权重拆不可用度：pt_i* = (1.5 pt − 非域暂停项) · n_i / Σn，允许中断率 λ_i* = pt_i* · 3600 / (A* · p̄_i)（p̄_i = 该类每次事件在机制集下的平均停顿，秒），改进倍数 k_i = λ_i / λ_i*（> 1 须改进，< 1 有余量），允许 FIT = 当前 FIT / k_i。每个硬中断都停作业 → E_i = 1；各类整窗暴露 → t_i = T；参考目录把所有类都归一到每卡·小时 → n_i = N 相同，AGREE 退化为 18 类等分（HAC-D 分配页的 coincidingMethods 会提示这一点）。非域暂停项（亚健康隔离、静默错误即时检出、预测误报）作为固定子系统先扣除。再分配：有余量的类不恶化、保留现状，余量按同一权重补给超预算的类（逐轮直到稳定），得 k′_i——它才是硬件任务。机制选择（AGREE 两阶段）：① 按类补缺——每步加入"对超预算类消除的超预算量 ÷ 工作量"最大的机制；② 造余量——若目标仍未在名义与降额下成立，而剩余超预算类已无机制可用，则按 A_op 增益 ÷ 工作量加入作用于已达标类的机制，其余量经再分配补给前者。复算：各类按 λ_i* 缩放后用引擎重算 A_op 应回到 98.5 %。

跨规模结论：① 仅改硬件时 AGREE 等分预算在 10 万卡让 13 类超预算（CORE ×4.2、UNKNOWN ×3.7、MEMT ×3.6），BOXIO / OPT / FABRIC 有余量；按"余量类不恶化"再分配后与 Albert 最小努力法完全一致，而 ARINC 让全部类同比 ×1.68——方法只改变"在类之间怎么拆"，总预算相同；② 机制改变的是各类的停顿 p̄_i，从而改变允许中断率 λ_i* = pt_i*·3600/(A*·p̄_i)：有梯级（r / p / e）的类停顿从 265 s 降到 5 s 一级，预算余量反过来接济无梯级的 POWER / COOL / MGMT / STORAGE / UNKNOWN；20 万卡因此达标（99.07 / 降额 98.72 %），方案后无硬件任务；③ 50 万卡无可行集（98.01 %）：AGREE 把剩余缺口折成 3 类的硬件任务（UNKNOWN ×2.3，POWER ×1.30，STORAGE ×1.04），其余 15 类不动——比 ARINC 等比 ×1.38 便宜得多，但这 3 类正是没有任何机制覆盖的事件，只能靠硬件或新梯级；④ AGREE 两阶段选集与规划器的差别：10 万卡 R-REPLAY + D-RECOVERY-CLASSIFY（98.75 %）vs 规划器 R-REPLAY + R-PROCESS（98.86 %）；按类补缺先取单类消除量最大的廉价项，造余量阶段才补 R-ELASTIC 这类"对已达标类再加码"的机制，所以 20 万卡集更大（工作量 27 vs 17）但校核概率更高（99.8 % vs 96.0 %）；上限 ReMAP 原有机制 182k 卡、新增 16 项机制（临时假设） 135k 卡、原有 + 新增（临时假设） 378k 卡；⑤ 敏感性：若复杂度按物理单元数（卡 / 节点 / 机柜 / 分区）计，机柜级与分区级的类预算缩小 256–14k 倍，POWER / COOL / STORAGE 的 k 升到 ×188 / ×113 / ×8400（10 万卡）——AGREE 的结论取决于"模块"的定义，参考目录按每卡·小时归一是本报告采用等分的原因。
