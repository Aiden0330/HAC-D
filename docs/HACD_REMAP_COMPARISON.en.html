HAC-D vs ReMAP and the reference engine: data provenance, the 950 result differences and the availability formulas

Subjects: github.com/lzq0927/remap (local remap/remap-latest) and github.com/zy009197/ai-cluster-reliability (local ai-cluster-reliability-main, catalog review-2026-10-09); the other report is ~/Documents/projects/output/HAC-D-950-910C-default-six.html (HAC-D v4.3 dd1fc99, 2026-10-20); the scaling report is docs/ASCEND950_SCALING_RELIABILITY. All with the six default mechanisms and a 30-day synchronous training job.

  • Data provenance matches: the local ReMAP clone moved from eaacb05 to f53ab7e (3 upstream commits, analysis and reporting features only, no catalog or parameter change); the local reference engine is byte-identical to GitHub 683afe8. HAC-D’s 54 events, 8 mechanism parameter sets, applicability lists, 16 baseline settings and the 16-mechanism audit data equal both repositories (all 8 checks pass).
  • The difference is HAC-D’s topology layer: the repositories rate events per card (“not device FIT”); HAC-D’s templates convert them per hardware unit under the CloudMatrix384 geometry, re-count them for the target topology and add 6 analogue classes on the scale-out network. Hard FIT per NPU at 10k: 910C 3,371.3 (+1.1 %), 950 3,092.1 (-7.2 %) — per card the 950 has half the cabinets and CPUs and 1/7 of the UB optical links.
  • The other “950 与 910C” report is reproduced value by value (56 / 56): it is the HAC-D v4.3 template default. Its difference from the scaling report’s 950 main case comes only from the scale-out assumption (template 2 planes × 3 tiers at radix 128 vs 4 planes × 2 tiers at radix 1,024), +0.0068 pt of A_op at 500k; the second architecture differs (910C vs UBL128).
  • Formulas: HAC-D’s A_op and ReMAP’s “operational availability” are the same quantity; ReMAP’s headline “availability” is retained clean progress, HAC-D’s delivered goodput. On the same event rates the engines differ by at most 0.0152 pt of A_op and 0.45 pt of goodput, of the order of the Monte Carlo intervals.

3. The availability formulas of HAC-D and ReMAP

HAC-D (closed form, steady-state renewal on the running clock)
A_run = 1 / (1 + [Σᵢ λᵢ t̄ᵢ + λ_iso R_iso + λ_det R_det + λ_FA R_FA] / 3600)　·　A_op = A_run · (1 − φ_SDC)
λᵢ = n_u · FITᵢ · 10⁻⁹ /h　·　t̄ᵢ = E[detection + replay / elastic / process / global recovery]　·　R_iso = 252 s　·　R_det = 3 s
G_delivered = SDC_window( G_clean , ν , 120 h , retain-last-clean )，G_clean = [1 − δ/τ − (P_rb·τ/2 + R̄)/M] × slowdown × (1 − local) × (1 − blocked)
ReMAP / reference engine (review-retained-progress, Monte Carlo over 720 h windows)
λ_hard = N / (10,000 × 30 h) = N · 3,333.3 · 10⁻⁹ /h　·　λ_slow, λ_sdc by shares 0.02 / 0.014　·　events drawn ∝ FIT within a class
T = correct + downtime + save + slowdown + rollback + terminalInvalid + localLoss　（closes in every trial）
operational availability = E[1 − downtime / T]　·　availability (headline) = E[correct / T]，correct = progress at T or the last clean checkpoint

  • Isolation of sub-healthy units: ReMAP detects after a fixed 5 min and the episode lasts a fixed 24 h, so every detected episode is isolated; HAC-D uses competing exponentials, 0.95 × 24 / (24 + 1/12), 0.35 % fewer (≈ 0.0007 pt of A_op at 500k).
  • Detected silent corruption: ReMAP pauses 2 s (1 s detection + 1 s recovery) and books the 1 s redo as rollback; HAC-D counts all 3 s as pause (≈ 0.0006 pt at 500k).
  • Checkpoint save: HAC-D’s first order takes δ/τ = 1/60 = 1.667 % over the whole window; ReMAP saves only while running, δ/(τ+δ) × running share (1.561 % at 500k).
  • Downtime term: HAC-D’s first-order goodput uses R̄/M on the event clock (4.54 % at 500k), slightly above the exact 1 − A_op (4.34 %); ReMAP’s downtime (4.34 %) matches the latter.
  • Window and manual fallback: ReMAP starts clean, clips downtime at the window end and draws the 7,200 s manual fallback with 1 % probability; HAC-D takes the steady state and the 252 s mean — same mean, only the variance differs.
  • Variance from silent corruption: undetected episodes are rare but each can cost up to 120 h of progress, so ReMAP’s retained progress is heavy-tailed (±0.5 pt 95 % interval at 500k); this is the main source of the goodput differences.
