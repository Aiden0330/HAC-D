对象：github.com/lzq0927/remap（本地 remap/remap-latest）与 github.com/zy009197/ai-cluster-reliability（本地 ai-cluster-reliability-main，目录 review-2026-10-09）；另一份报告为 ~/Documents/projects/output/HAC-D-950-910C-default-six.html（HAC-D v4.3 dd1fc99，2026-10-20）；本项目报告为 docs/ASCEND950_SCALING_RELIABILITY。全部为六个默认机制、30 天同步训练作业。

  • 数据来源一致：本地 ReMAP 从 eaacb05 更新到 f53ab7e（上游新增 3 次提交，均为分析与报告功能，不改目录与参数）；参考引擎本地副本与 GitHub 683afe8 逐字节一致。HAC-D 的 54 个事件、8 个机制参数、适用事件、16 项基线设置与 16 项新机制数据与两个仓库完全一致（8 项检查全部通过）。
  • 差别在 HAC-D 的拓扑层：仓库按每卡 FIT 计率（“非物理器件 FIT”），HAC-D 的拓扑模板把它在 CloudMatrix384 几何下换算到每个硬件单元、再按目标拓扑的单元数加总，并给 scale-out 网络新增 6 类类比事件。于是 1 万卡时每 NPU 硬中断 FIT：910C 3,371.3（+1.1 %），950 3,092.1（-7.2 %）——950 每卡的机柜、CPU 只有一半，UB 光链路只有 1/7。
  • 另一份“950 与 910C”报告被逐值复现（56 / 56 个数）：它就是 HAC-D v4.3 模板默认。与本项目 950 主算例的差别只来自 scale-out 假设（模板 2 平面 × 三层 radix 128 对主算例 4 平面 × 两层 radix 1,024），50 万卡 A_op 差 +0.0068 pt；第二个架构不同（910C 对 UBL128）。
  • 公式：HAC-D 的 A_op 与 ReMAP 的“运行可用度”是同一个量，ReMAP 的主指标“可用度”是保留正确进度，对应 HAC-D 的正确有效产出。在同一事件率下，两个引擎的 A_op 最大差 0.0152 pt，有效产出最大差 0.45 pt，均在蒙特卡洛区间量级内。

3. HAC-D 与 ReMAP 的可用度公式

HAC-D（闭式，运行时钟上的稳态更新过程）
A_run = 1 / (1 + [Σᵢ λᵢ t̄ᵢ + λ_iso R_iso + λ_det R_det + λ_FA R_FA] / 3600)　·　A_op = A_run · (1 − φ_SDC)
λᵢ = n_u · FITᵢ · 10⁻⁹ /h　·　t̄ᵢ = E[检测 + 重执行 / 弹性 / 进程 / 全局恢复]　·　R_iso = 252 s　·　R_det = 3 s
G_delivered = SDC_window( G_clean , ν , 120 h , retain-last-clean )，G_clean = [1 − δ/τ − (P_rb·τ/2 + R̄)/M] × 降速 × (1 − 局部) × (1 − 阻塞)
ReMAP / 参考引擎（review-retained-progress，720 h 窗口蒙特卡洛）
λ_hard = N / (10,000 × 30 h) = N · 3,333.3 · 10⁻⁹ /h　·　λ_slow, λ_sdc 按份额 0.02 / 0.014　·　类内按 FIT 抽事件
T = correct + downtime + save + slowdown + rollback + terminalInvalid + localLoss　（逐次试验闭合）
运行可用度 = E[1 − downtime / T]　·　可用度（主指标） = E[correct / T]，correct = 窗口末进度或最后干净检查点

  • 亚健康隔离：ReMAP 检出固定 5 min、片段固定 24 h，凡检出必隔离；HAC-D 用竞争指数，隔离概率 0.95 × 24 / (24 + 1/12)，少 0.35 %（50 万卡对 A_op 影响约 0.0007 pt）。
  • 即时检出的静默错误：ReMAP 停机 2 s（检测 1 s + 恢复 1 s）、1 s 重算记为回滚；HAC-D 把 3 s 都记为暂停（50 万卡约 0.0006 pt）。
  • 保存开销：HAC-D 一阶式取 δ/τ = 1/60 = 1.667 % 且作用于整个窗口；ReMAP 只在运行时保存，比例 δ/(τ+δ) × 运行份额（50 万卡 1.561 %）。
  • 停机项：HAC-D 有效产出的一阶分解用事件钟上的 R̄/M（50 万卡 4.54 %），比精确运行份额 1 − A_op（4.34 %）略大；ReMAP 的停机（4.34 %）对应后者。
  • 窗口与人工兜底：ReMAP 从干净状态开始、窗口末截断停机，人工兜底按 1 % 概率抽 7,200 s；HAC-D 取稳态与均值 252 s——均值相同，只影响方差。
  • 静默错误的方差：漏检静默片段稀少但每次可丢失最多 120 h 进度，ReMAP 的保留正确进度呈重尾，95 % 区间在 50 万卡约 ±0.5 pt；这也是两者有效产出差异的主要来源。
