HAC-D 用户手册

面向昇腾 NPU 训练集群的可用性、MTBF、MTTR 与 goodput 建模：三种拓扑模板转换为硬件数量与各单元的故障类型，配合故障管理机制，在硬件 FIT、机制与恢复上限之间按三种策略分配目标；解析式带有效性标记，解析式不成立时转蒙特卡洛，每个数字都带公式与口径（事件、分母、层级）。版本 4.0，2026-10-18。

1. HAC-D 是什么

HAC-D 把集群拓扑（三种昇腾模板之一，或任意自定义描述）转换为硬件数量及各单元所带的故障类型，再转换为可用率、平均中断间隔、恢复时间、goodput 与成本，并把目标反向分配到硬件 FIT、故障管理机制与恢复上限。它以综述章节《AI 集群可靠性建模》为依据，并与一个独立的参考引擎（经审核的单训练作业 30 天离散事件仿真器）交叉校核。

1.1 原则

  • 每个数字都带公式与口径。故障率是「某事件类 / 某分母 / 某层级」（例如作业级的每卡·小时硬中断）。不同事件类的量永不相加。
  • 解析式优先，并带有效性标记。一阶 goodput 公式检查 τ + δ ≪ M 与 R ≪ M；标记触发时首要值切换为精确更新式。
  • 假设不成立时转蒙特卡洛。非指数寿命、相关故障、有限备件池、有限窗口与静默错误走仿真；解析式结果仍显示并带差值徽标。
  • 每个参数都有出处。参数库记录与方案输入带来源、年份与置信（measured、paper-reported、vendor、derived、assumed、scan-level）。
v4（2026-10-18）：NPU 工具，拓扑优先。首页把拓扑模板与规模转换为硬件清单与可靠性（§4）；ReMAP 六项机制默认启用，在机制页修改（§6）；分配页在硬件与机制约束下用三种策略达到目标（§7）。训练作业页并入为「可靠性」页签，审核页并入机制页与分配页。v3.7 的 GPU 示例与界面用语已从界面移除（命令行与 MCP 仍可按 ID 取用；GPU 工具可从 git 标签 v3.7-gpu 分出）；GPU 集群实测数据作为已标注的类比保留在参数库中，因为昇腾没有公开的故障数据。

3.2 故障类别

每个部件类可建模三种表现，各有自己的口径与处理方式：

  • 中断：单元停止；作业被检测为停机，经机制链与全局 checkpoint 恢复，除非由不回滚的机制处理，否则回退到最近 checkpoint。
  • 亚健康（fail-slow）：单元以性能因子 φ 持续运行一段时间；同步作业被拖慢（掉队者定律）；策略为容忍或隔离（已检出的单元先保存进度再切出）。
  • 静默错误（SDC）：状态被污染而无中断；即时检测捕获一部分，漏检的污染在兜底时延后被发现并回退到最后一个干净 checkpoint；窗口结束时仍带错的状态判废。

3.3 置信与出处

每个故障率或时间可带 provenance（来源、机构、年份、URL、算式）与置信标签。参数库（§12.3）使用同样的标签；参考示例把借用的占比与目标值标为 assumed。规划器（§6.3）与分配策略（§7.1）对机制参数降额；经典分配方法按置信加权可行性。v4 各单元的故障类型（§4.3）是目录先验值换算到硬件单元，仍标为 assumed。

4.2 规模与硬件数量

规模按钮设定作业 NPU 数（10k、100k、200k、500k，或在输入框中填任意 N；自动生成的方案名随规模更新）。数量按模板几何推算：节点 = ⌈N ÷ 每节点 NPU⌉，CPU = 节点 × 每节点 CPU，计算柜 = ⌈节点 ÷ 每柜节点⌉；超节点模板中，超节点 = ⌈节点 ÷ 每超节点节点⌉，L1 = 节点 × 每节点 L1，L1–L2 链路 = L1 × 每 L1 链路。未满的最后一个超节点，其 L2 芯片与通信柜按已部署节点计算（按需：每子平面 ⌈子平面链路数 ÷ L2 端口数⌉ 片，允许 L1–L2 并行链路；整个超节点则按整柜采购计）。scale-out 网络是覆盖各 NPU 端口的折叠 Clos：交换机端口数 k、叶收敛比 o 时，叶交换机有 d = ⌊k·o/(1+o)⌋ 个下行口，t 层可承载 d·k·(k/2)^(t−2) 个端口；第一层 ⌈P/d⌉ 台，中间层 ⌈H/(k/2)⌉，顶层 ⌈H/k⌉，H = ⌈P/o⌉；k = 64 时 10,000 个端口需三层（313 + 313 + 157 台，30,000 条链路），100,000 个端口需四层（3,125 + 3,125 + 3,125 + 1,563 台，400,000 条链路）。

4.4 输入分组

  • 硬件参数（随模板而变）：每柜服务器或节点数、每超节点机柜数、每节点 CPU 与 L1 芯片数、子平面数、L2 芯片数与端口数、每片 L1 链路数、每链路光模块数、交换填充方式；scale-out 网络的开关，以及每 NPU 端口数、交换机端口数与收敛比。公开资料未给出的字段标为 assumed。
  • 故障库：已修改的 FIT 数量、恢复库默认值、跳转故障库页。
  • 机制：已应用机制以标签显示——默认为 ReMAP 六项 D-SDC、R-SDC、R-REPLAY、R-PROCESS、R-ELASTIC、C-FAST——并可跳转机制页；参数、恢复链顺序与静默错误策略都归机制页所有。
  • 负载、检查点与目标：窗口长度、τ 与 δ（被机制接管时只读，例如应用 C-FAST 后显示“由 C-FAST 设定”）、A_op 目标与正确有效产出目标。
  • 恢复（MTTR 混合）：检测覆盖率、自动检测与超时、自动尝试时间与成功率、人工时间，并给出 R̄ = T_det + T_auto + (1 − p_s)·T_manual；接管检测的机制（D-HARD）会使这些字段只读。
  • 方案文件：导出 JSON、重置模板、打开方案编辑器。

在已应用机制之下的每次编辑都作用于“裸”设计：先精确移除这些机制，修改后再按原顺序与参数重新应用。因此修改 FIT 不会丢失机制，被机制接管的设置仍由该机制决定。

6.2 归因

6.3 机制规划（分配页）

6.4 静默错误与恢复链页签

作业级：即时检出率 q 与检测时间、兜底发现时延 D（参考基线为 120 h）、可选的 step 恢复（最多重做 t_step，用 t_rec 恢复），以及窗口的期末规则：保留最后干净检查点（经审核的参考引擎，默认）或期末未解决则整窗口清零（参考工具 V4 与 ReMAP 历史模型的 delivery 口径；两者是不同指标，可靠性页签同时给出两个值）。恢复机制链可启用重执行（不回滚）、DP 域弹性（不回滚；n 个域中一个域不可用 t_el，全局同步 t_sync）与进程重调度（回滚），各带成功率与成功 / 失败耗时；梯级顺序控件设定含检测时延的梯级的尝试顺序（↑ 提前一级；预测与网络切换始终在前），之后才是全局 checkpoint 恢复。v4 起本页签是这些设置的唯一归属处：打开某一梯级或检测即应用对应的机制库机制，修改任一参数即按新参数重新应用（应用记录与方案永不矛盾），关闭则精确移除；兜底时延、期末规则与梯级顺序不属于任何机制，直接修改。在方案编辑器中，每个部件类还提供由事件计数估计故障率：去重事件数 ÷（单元数 × 观测小时）给出故障率、FIT、MTBF 与精确 Garwood 区间（零事件时给单侧上界），一键写入该类作为实测故障率并记录推导。

  • 恢复杠杆：把恢复参数推到上限——自动尝试 ≥ 60 s、自动成功率 ≤ 99.9 %、人工恢复 ≥ 30 min（上限与工作量 3 / 3 / 2 为可修改的假设）；
  • 硬件：每个故障类的中断 FIT × xᵢ ∈ [下限ᵢ, 1]；工作量 eᵢ·log₂(1/xᵢ)，eᵢ 为该类 FIT 每减半的工作量（默认 2），下限ᵢ 为该类可达到的当前 FIT 最低比例（默认 0.05）。下限、工作量与固定类保存在方案中（component.allocation）。
策略规则
最优在候选手段的各子集上求总工作量（机制 + 杠杆 + 硬件）最小：A_op 下最多 10 个手段、正确有效产出下最多 6 个时精确枚举（A_op 的硬件水平用闭式求出，所选方案再用引擎确认），超出时按总工作量贪心下降；最便宜的若干方案列为备选
MTTR 降低优先先恢复侧：每步加入单位工作量收益最大的机制或杠杆，直到目标满足或不再有收益；剩余缺口交给硬件
MTTF 提升优先先硬件，降到下限为止；只有下限仍不够时才加入机制（先物理类，再恢复侧，均在硬件处于下限时评估），之后再把硬件放宽回去

硬件分配方式。对由引擎二分求出的水平 L，xᵢ·cᵢ = clamp(wᵢ·L, 下限ᵢ·cᵢ, cᵢ)，其中 cᵢ = λᵢ·p̄ᵢ 是该类的暂停贡献（故障率 × 其机制链每次事件平均暂停）。最小工作量（默认）取 wᵢ = eᵢ，对 A_op 预算使 Σ eᵢ log₂(1/xᵢ) 最小；AGREE 取 wᵢ = 单元数 × 重要度，并把低于预算的类的余量再分配；ARINC 取 wᵢ = cᵢ（统一比例）。对 A_op，运行占比精确为 1/(1 + (Σ xᵢcᵢ + F)/3600)（F：隔离、误报与已检出静默错误的暂停），由此可闭式求出水平。目标已满足时结果给出硬件余量：所有中断 FIT 同比放大多少倍目标仍成立。

7.5 经典方法页签自上而下算什么

  1. 静默错误与正确交付目标（正确交付口径）。正确交付目标 G_d 除以交付系数 f = 正确交付 ÷ 有效，再除以亚健康 / 备件 / 域损失系数 φ，得到有效目标与中断项目标。卡片先问仅靠硬件能否达到 G_d（所有故障率 → 0、静默策略不变）；若不能，则报告硬件不变时达到目标所需的最小即时检出率 q*、检出率不变时所需的最长兜底发现时延 D*，并以检出率提高到 q* 计算下方预算。若 q = 1 仍达不到，预算按 q = 1 计算，显示中断侧还须补足多少（说明中会写明）。
  2. 窗口账本损失预算。允许损失 (1 − G*) × 窗口（百分比与小时）按所选权重拆到九个账本项（停机、checkpoint 保存、回滚、亚健康降速、弹性域损失、备件耗尽、机制开销、静默回滚、期末判废）；每项给出当前、允许、超出与驱动该项的杠杆。拆分是记账目标，不证明各项能独立达到。
  3. 预算卡片（与方法无关，Young 间隔下的一阶式）：损失预算 1 − G_中断 与当前硬中断损失对比；保持 R、压缩 λ 给出所需 MTBI 与改进倍数；保持 λ、压缩 R 给出所需恢复时间；均衡分配按重启项占比分配预算。当前损失已在预算内时卡片显示余量（倍数小于 1）。
  4. 各部件类允许的故障率：所需作业中断率 λ* 按方法拆分；每类列出当前合计率、分配率、每单元允许率（每 10⁶ 单元·小时）、改进倍数（当前 ÷ 分配；小于 1 表示可以恶化）与可行性标记（ok，或比该类已知最优值更严）。
  5. 各恢复阶段允许的时间：所需恢复时间按各阶段（检测、自动尝试、人工份额，或流水线各阶段）当前时间超出下限的部分按比例拆分。
  6. 可用率目标分解（设定 A* 时）：各类 ln Aᵢ = (wᵢ/Σw) ln A*，并给出对应的允许故障率与 MTTR。

13.6 机制链

13.7 静默错误（有限窗口）

ν = λ_sdc (1 − q) · A_run · (1 − P_clear)，P_clear = 1 − (1 − e^{−λ_rb L})/(λ_rb L)（首个带错 checkpoint 写入前的回滚会清除污染） S_k = Γ(k, ν) + (k − 1)(D + R_c)；P(S_k ≤ y) = P(Poisson(νz) ≥ k)，z = y − (k − 1)c E[N] = Σ_k P(S_k ≤ T)；E[带错] = Σ_k ∫₀ᴰ P(S_k ≤ T − x) dx；E[停顿] = Σ_k ∫_D^c P(S_k ≤ T − x) dx 正确交付 = [g·(T − E[带错] − E[停顿]) − U·E[N]]/T，U = (τ²/2 + τδ)/(τ + δ)；已检出的静默：带停顿 t_d + G 的回滚事件，或 step 恢复下的仅停顿事件

13.8 归因与规划

Shapley：φᵢ = Σ_{S∌i} |S|!(n−|S|−1)!/n! · [v(S ∪ {i}) − v(S)]，Σ φᵢ = v(全部) − v(∅)；交互项 = Δ − Σ 单项收益 规划器：可行 S ⇔ v(S) ≥ G* 且 v_derated(S) ≥ G*；规划 = 工作量最小；必要 = ∩ 可行 S；(工作量, v) 的 Pareto 前沿；校核 P(窗口 ≥ G*) ≥ 置信

13.9 分配与备件

goodput 预算（Young）：L = √(2δ/M) + R/M；保持 R：√(2δ) s + R s² = L*，s = M^{−1/2}；保持 M：R* = M (L* − √(2δ/M)) 正确交付口径：有效目标 = G_d / f_SDC；中断项目标 = 有效目标 / (φ_job (1 − P_blocked)(1 − ℓ))；q*、D* 用二分法求 可用率分解：ln Aᵢ = (wᵢ/Σw) ln A*；λᵢ = Uᵢ/(MTTRᵢ(1 − Uᵢ)) 热备：满足 P(Binomial(N_nodes, p_daily) ≤ k) ≥ q 的最小 k；Poisson(N λ T_replenish) 分位数；维修流水线 Poisson(N λ f_hw L) 分位数 推理：u_r = λ_r MTTR_r/(1 + λ_r MTTR_r)；A_any = 1 − u_r^{n+k}；A_cap = Σ_{j≤k} C(n+k, j) u_r^j (1 − u_r)^{n+k−j}

13.10 v3.5 新增：期末规则、统计、上界、损失预算、事件计数

期末规则 discard-all：正确交付 = Σ_{n ≤ T/c} Poisson(n; ν(T − nc)) · [g(T − nc) − U n]⁺ / T；P(期末未解决) = 1 − Σ_n Poisson(n; ν(T − nc))（retain-last-clean 见 §13.7） 统计：均值 ± t_{0.975, n−1}·sd/√n（Student-t），type-7 分位数；P(窗口 ≥ 目标) 带 Wilson 区间 [(p + z²/2n) ± z√(p(1−p)/n + z²/4n²)]/(1 + z²/n)；对照置信水平给出 支持 / 不确定 / 未达到 检查点上界：S 秒窗口内 goodput ≤ (⌊S/L⌋τ + min(S mod L, τ))/S，L = τ + δ；长期 ≤ τ/L；目标高于最优组合的上界 ⇒ 已证明不可达 损失预算：允许_i = (1 − G*) · w_i，Σ w_i = 1（按比例 / 均分 / 自定义）；超出_i = 当前_i − 允许_i；小时 = 份额 × 窗口 事件计数：λ = k/E，FIT = λ·10⁹；Garwood [χ²_{α/2}(2k)/(2E), χ²_{1−α/2}(2k+2)/(2E)]；k = 0：上界 χ²_c(2)/(2E) = −ln(1 − c)/E

13.11 v4 新增：拓扑数量、单元故障类型、分配策略

数量：节点 = ⌈N/n_node⌉，CPU = 节点·c，机柜 = ⌈节点/n_cab⌉，超节点 = ⌈节点/n_pod⌉，L1 = 节点·l1，链路 = L1·l_L1；最后一个超节点（按需）：每子平面 L2 = min(L2_pod, ⌈r·l1·l_L1/(子平面·端口)⌉) P 个端口、端口数 k、收敛比 o 的 Clos：d = ⌊k·o/(1+o)⌋，t = min{t : P ≤ d·k·(k/2)^(t−2)}，第一层 ⌈P/d⌉，中间层 ⌈H/(k/2)⌉，顶层 ⌈H/k⌉，H = ⌈P/o⌉，链路 = P + (t−1)·H 单元 FIT：FIT_unit = FIT_card × 384 / CloudMatrix384 一个超节点中的单元数；λ_job,hw = Σ_单元 数量 × FIT_unit × 10⁻⁹ 策略：x_i·c_i = clamp(w_i·L, floor_i·c_i, c_i)，c_i = λ_i·p̄_i；w_i = e_i（最小工作量）| n_i·E_i（AGREE）| c_i（ARINC）；硬件工作量 = Σ e_i·log₂(1/x_i) A_op 水平的闭式：Σ x_i c_i ≤ 3600·((1 − φ_sdc)/A* − 1) − F；可行 ⇔ 名义与降额均 ≥ A*；余量 = 目标仍成立时所有 FIT 的最大同比倍数

15. 推荐工作流

  1. 拓扑与规模：选择与设计相符的模板（A2、A3、Atlas 950），设定作业 NPU 数与硬件参数；检查假设字段。
  2. 硬件与故障类型：阅读 10k–500k 的硬件清单；有实测值时替换库中 FIT（按单元；区间可用方案编辑器中的事件计数估计）。
  3. 机制：保留或调整默认六项，设定参数与恢复链顺序，检查静默错误策略；用归因（Shapley）看各机制的贡献。
  4. 评估：指标条与「可靠性」页签——A_op、正确有效产出、MTBI、区间标记、窗口账本。
  5. 分配：设定目标与约束（FIT 下限、每减半工作量、候选机制、恢复上限），对比三种策略，再跨规模运行；把各单元允许 FIT 交给硬件负责方，把机制组合与恢复上限交给平台团队。
  6. 校核与报告：账本校核（P(窗口 ≥ 目标) 及 Wilson 判定）、非指数或相关输入时用仿真页、报告页及其导出；然后在生产中实测并循环。

17. 局限与路线图

  • 解析式假设指数寿命与修复、故障独立（共因只通过 β）；仿真放宽这些假设。
  • 机制链的弹性一级是容量模型（一个域不可用，其余继续）；它不是同步训练的性能承诺，且需要机制库列出的前置条件。
  • 静默错误与参考工具一样采用固定兜底时延且同一时刻只有一个事件；期末规则可选保留最后干净检查点或整窗口清零，但保留窗口与定位 / 验证成功率不是独立参数。
  • 机制库的参数是参考目录与文献的目标值与先验（已标注）；降额是一种约定，不是实测。事件计数的区间只覆盖 Poisson 抽样误差。
  • 未建模：参考工具 V4 引擎的拓扑特性（放置方式、维修并发数、最低可用容量）；ReMAP 桥接会注明引擎无法表示的梯级与开销。
  • v4 拓扑模板：A2 的 Clos 端口数与收敛比、Atlas 950 的交换结构以及所有光模块数量均为假设；RoCE 交换机与链路使用 UB 类比值；机柜 FIT 不随密度变化；各单元故障类型是在 CloudMatrix384 几何下换算的目录先验值，并非实测。
  • 分配策略只通过候选机制的库参数与三项恢复杠杆改变机制参数，不对每个机制参数做连续优化。硬件工作量采用每减半的对数代价，是有成本曲线时应替换的假设。
  • 待办：上传拓扑图片的图像识别（目前模板是参数化示意图）、DP 弹性训练模板、Shapley 的蒙特卡洛置信区间。
