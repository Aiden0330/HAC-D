昇腾 AI 集群架构与拓扑（2026-10-20 修订）：从 CloudMatrix384 到 Atlas 950 超节点、SuperPoD Flex / UBL128 与超节点集群

本页合并三部分：10-16 版的三代拓扑；10-19《昇腾下一代集群综述》中复核后的证据[30]；10-20 收到的两份附件（“昇腾950C … 50万卡硬件工程量”调研报告 PDF 与同名仪表盘）中经核对可用的信息[29]（逐条判定见第 8 节）。证据标签：华为确认华为论文客户确认媒体分析师未证实相互矛盾推导；推算附算式；计数来自 HAC-D v4.3 引擎（a950-ub2 等模板）。图为按资料重绘的示意图。1 万–50 万卡的机柜与器件数、六个默认机制下的可用度 / MTBF / MTTR、架构映射与瓶颈见配套报告[31]。

  • Atlas 950 有两种规模，不能混用：产品页现行规格为 16 计算柜 + 4 灵衢互联柜、最多 1,024 颗 950DT（WAIC 2026 展出真机）；8,192 卡、128 + 32 柜是 HC2025 路线图，截至 2026-10-19 没有建成或交付的公开证据[1,3,2]。两种规模每 NPU 的器件数相同，HAC-D 的可靠性数字也相同，只有超节点数与超节点级共因的波及范围不同。
  • 柜间是一层光交换 Clos：每 NPU 2 × 800G LPO 上联 4 个灵衢互联柜中的交换机（约 16 台，推算），LightCounting 数到每计算柜 128 只、全系统约 4,096 只（含两端）[4,6]。“UB-Mesh 递归直连”应理解为拓扑家族与逻辑全可达；柜内第二维是直连 Mesh + LRS 还是背板 Clos 仍未定[5]。
  • 超节点之间的 scale-out 未公开：华为只说 Atlas 950 SuperCluster 支持 UBoE 与 RoCE[2]；“两层 Clos、四平面、51.2 万卡”是 HC2026 对昇腾 960 超节点集群的陈述[11]，附件把它记到 950 名下。按 Clos 自洽：每平面 12.8 万端点时两层需要 radix ≥ 512，星河 UBG 的 radix 1,024 两层每平面可到 524,288[13]。
  • 新增：SuperPoD Flex / UBL128：华为计算官微（2026-09-30）称与 DeepSeek 联合定义 128 卡 3.2 Tbps 单层交换的超节点与 256K 卡两层交换 scale-out[16]；机柜与交换机数未公开。附件引用的 375 / 347 GB/s 是 DeepEP-Ascend 在预发布 PoC HDK、netlayer 1 上的 EP8 上限，README 未提 UBL128[17]。
  • 部署证据：没有任何互联网公司公布过精确的昇腾卡数；最强的一手证据是客户代码（DeepEP-Ascend、TileKernels、verl 950DT 镜像）。中国移动 6,208 卡集采只到招标阶段，华为云 AICS 950 服务仍为公测，首个 950DT 商用局点（通州）是风冷 Atlas 850E[17,19,22,20,21]。
  • 可靠性：公开数字口径各不相同，均不能当作作业中断率（第 7 节）。HAC-D 在六个默认机制下给出：A_op 99.92 %（1 万卡）→ 96.15 %（50 万卡），跌破 98.5 % 约在 190k（原生）/ 201k（UBL128）卡；停机的约 89 % 来自没有快速恢复梯级的类别[31]。

2. Atlas 950 超节点（现行规格 1,024 卡）

2.1 规格（产品页中英文，2026-10-20 复核）[1]：

  • 16 计算柜 + 4 灵衢互联柜，均为 44OU、2,250 × 600 × 1,400 mm；计算柜 1,700 kg、约 100 kW
  • 每柜 64 × 950DT（96 GB、4.0 TB/s）+ 16 × 950 CPU（最高 96 核、2.3 GHz）、192 个 DDR5-6400 插槽
  • 每柜 58.8 PFLOPS mxFP8 / HiF8、114.1 PFLOPS mxFP4、31.1 PFLOPS FP16；整套 1 EFLOPS FP8（英文页 0.9）、2 EFLOPS mxFP4
  • UB 每 NPU 1.68 TB/s（双向）、整套 1.72 PB/s；256 TB 全局统一编址；跨柜 RTT 3 µs[3]
  • 供电：380 V AC 与 336 V / 240 V 直流的两路组合；液冷（中文页：计算柜与互联柜均液冷；英文页写液冷 + 风冷）
  • 可靠性：闪断自恢复、传输层重传、降 lane 不断链、跨柜全光 2+2 光路保护；支持 64 或 1,024 卡配置，页面不含 8,192

2.2 互联：每柜 8 个 NPU 托盘（每托盘 8 卡，托盘内电链路全互联）+ 8 个 CPU 托盘，前插托盘与后插板正交互连[4]；芯片 18 个 x4 端口中 15 个合 1.68 TB/s（推算），可能的分配是 7 + 4 + 4 或 7 + 8[8]。柜内第二维：UB-Mesh 参考设计为直连 2D 全互联 + 每柜 72 片 LRS（HAC-D 采用）[5]，LightCounting 读作背板 Clos。柜间：每 NPU 2 × 800G LPO（2+2 保护）进入 4 个灵衢互联柜里的一层交换，交换机型号与台数未公开；按 Hot Chips 8K 示例（128 台 100T）缩放得 16 台[6]。冗余：64 + 1 备份 NPU 与 N + 1 备用柜只见于论文和讲稿，产品资料均按每柜 64 卡；单只光模块故障在 2+2 与降 lane 下属降级或亚健康，路由不可收敛时才隔离 NPU[7]。

3. 超节点之间：SuperCluster 与 scale-out

HC2025 的 Atlas 950 SuperCluster 为 64 个 8,192 卡超节点、52 万多卡（64 × 8,192 = 524,288，推导）、1 万多个机柜，支持 UBoE 与 RoCE，华为称 UBoE 时延更低、可靠性更高、交换机与光模块更少，但没有数值[2]。芯片侧每 NPU 2 × 400G UBoE，可拆为 4 × 200G，与 UB 共用 SerDes[8]。平面数、层数、交换机 radix 与收敛比对 950 都未公开；券商估 UBoE 约 3.9 万台交换机、222 万只光模块，RoCE 约 4.5 万台、300 万只，追溯不到华为原文分析师[24]。HC2026 首次给出“两层 Clos、四平面、51.2 万卡（多轨约 100 万）”，对象是昇腾 960 超节点集群[11]；同期星河 UBG 交换机 radix 最高 1,024，SF9300 面向昇腾 A5 / A6、两层多平面去掉核心层[13,14]。两层非阻塞 Clos 每平面最多 radix² ÷ 2 个端点：radix 1,024 时 524,288，radix 128 时只有 8,192。因此附件的“两层四平面 + 64 / 128 口交换机”在 51.2 万卡下不成 Clos；配套报告取 4 平面 × 两层、radix 1,024 为主算例，三层 radix 128 与附件方案作敏感性。25.6 万卡 Atlas 950 集群“部署中”，客户、地点、协议与超节点规格均未披露（256,000 ÷ 1,024 = 250 可整除，÷ 8,192 = 31.25 不能）[10,15]。

4. SuperPoD Flex / UBL128 与 DeepSeek

华为计算官微（2026-09-30，经量子位授权转载）：华为向 DeepSeek 提供联合定义的昇腾超节点 SuperPoD Flex 与 UBL128 组网方案，实现 128 卡 3.2 Tbps 单层交换 scale-up 与 256K 卡两层交换 scale-out；在全互联的 UBL128 超节点上提供 ASC-COMM 通信编程库；DeepSeek 同日开源 TileLang 编译工具及 DeepGEMM、FlashMLA、TileKernel、DeepSelect、DeepEP 的昇腾版；华为自测 DeepSeek-V4.1-Flash 在 EP32、离线、128K 上下文下 TPOT 5 / 10 ms 时每卡 2,469 / 5,102 tokens/s华为确认[16]。未公开：机柜形态（950 液冷柜还是 850E 风冷）、交换机型号与台数、链路介质。DeepEP-Ascend README 的 dispatch 373–375 / combine 345–347 GB/s 是 EP8 每 rank 上限，EP128 降到 313–320 / 272–278，测于 netlayer 1、预发布 PoC HDK，README 没有 UBL128 一词客户确认[17]；EP 规模止于 128 与 128 卡单层域吻合，这一对应是推断。配套报告把 UBL128 建成 2 个 64 卡计算柜 + 4 台 128 × 800G 交换机（每 NPU 4 × 800G）、无柜内 LRS、4 个超节点共用 1 个交换柜（附件估算），全部标为假设假设。
