UB-Mesh（华为论文与 Hot Chips 2025 讲稿）描述了柜内 64 NPU 的 2D-FullMesh、Pod 级 4D-FullMesh 与其上的 Clos，8K 示例为 128 柜 × 64 NPU——与 Atlas 950 的 128 × 64 计数相同，但发布稿没有说明产品采用该拓扑，图 2 未据此作图。

  • 三层嵌套、两种网络：NPU → 节点（8 NPU）→ 超节点（一个 UB scale-up 域）→ 集群（RoCE 或 UBoE scale-out）。scale-up 域从 8（A2 服务器）扩到 384（A3 / CloudMatrix384），再到 8,192 / 15,488（Atlas 950 / 960），集合通信越来越多地留在 UB 域内。
  • 三个平面：UB（域内，每 NPU 392 GB/s）、RDMA / RoCE（域间，每 NPU 400 Gb/s）、VPC（擎天卡：存储、管理、外部）。A2 一代则是每 NPU 一个 200GE RoCE 口组成参数面。三个平面的故障是不同事件类，不能相加。
  • 互联器件远多于 NPU：CloudMatrix384 每颗 NPU 对应 14 条 L1–L2 光链路、1.17 片 UB 交换芯片；10 万卡时为 1,400,000 条链路、116,732 片 UB 芯片。L2 无阻塞且端口用满，单条链路或单片 L2 故障是 1/16 子平面的带宽降级，而不是断连。
  • 故障域：卡（1）· 节点（8）· 计算柜（32 / 64 / 约 88）· 超节点（384 / 8,192）· 通信柜（约 28 片 L2 的共因）· 集群服务（整个作业）。Atlas 950 / 960 的柜内互联与通信柜内部结构未公开；HAC-D 的 atlas950 预设沿用 CloudMatrix384 的结构参数（表 2 中带 * 的数）。

对分配的含义：目录按每卡·小时给 FIT，架构决定这些 FIT 落到多少个器件、一次事件停掉多少卡。CloudMatrix384 几何下，OPT 66.7 FIT / 卡 ≈ 4.8 FIT / 链路，FABRIC 66.7 ≈ 57 FIT / UB 芯片，POWER 166.7 ≈ 5,333 FIT / 计算柜（Atlas 950 的 64 卡柜加倍）。HAC-D 的计数作用域（l1_switch、l2_switch、subplane、optical_link、comm_rack、supernode）正是 v3.8 规划 WP1（按架构推导 AGREE 权重）的输入。
