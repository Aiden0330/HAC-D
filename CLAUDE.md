# HAC-D — AI cluster availability / MTBF / MTTR modeling tool

Plan: `docs/DEVELOPMENT_PLAN.md`. Evidence base: the survey chapter at `../survey/ai-cluster-reliability-modeling.html` (read-only; extract text with a script, it is too large to read whole).

## Layout
- `packages/core` — pure TypeScript numerics (no DOM). Modules: units, math, rbd, ctmc, checkpoint, sparing, mttr, scale, allocation, sensitivity, cost, mc, scenario; v5: records (topology record, failure-rate override, mechanism set — JSON in `packages/core/data/{records,fault-rates,mechanism-sets}`, every value with provenance and confidence), budget, layers, study/prune. Tests in `packages/core/test`, golden vectors in `packages/core/test/golden/golden*.json` (computed independently in Python; do not edit expected values by hand).
- `packages/core/src/ingest` (v6) — closed vocabularies, evidence cards (grounding, two-pass agreement), the 口径 normaliser (device FIT → business-impact FIT per unit), validation gates, the input / KPI delta, extension requests. Worksheets (Markdown profile `hacd-worksheet-1`) live in `packages/importers/src/worksheet`; the model adapters in `packages/agent`; the commands in `hacd ingest …`; the offline bundle in `scripts/bundle-offline.mjs`. Internal records keep their own ids beside the public ones.
- `apps/web` — Vite + React static app (bilingual zh/en, light/dark), compute in Web Workers. v6.3: Allocation › Report runs the pipeline of `hacd findings` on the active project in the worker (`reportFromScenario` in core, the recipes from `@hac-d/reports/browser`, KaTeX fonts fetched in `worker/katexCss.ts`); the Picture tab draws `@hac-d/reports/schematic`; the Hardware tab groups the units under the six layers.
- `packages/cli` — Node CLI over the core; `hacd findings | bom | budget | methodology | prune | study` regenerate the Ascend report set from the records (`docs/markdown/USER_GUIDE.md` "v5 CLI"; `hacd findings --data <dir>` re-renders the pages from a stored sidecar after a recipe change, then `node packages/reports/test/reproduce.mjs`); `hacd ingest template | fields | worksheet | import-fit | normalize | validate | dry-run | diff | promote | extract` is the v6 input pipeline ("v6 ingest"); `hacd ingest run` is the chain as one call with a `run.json` manifest, `hacd ingest protocol` the operator prompt / tool manifest for the on-prem model and `hacd ingest operate` the reference host that runs that model (`docs/markdown/AGENT_OPERATOR.md`); `scripts/mock-onprem-model.mjs` is the scripted stand-in the operator tests and the pilot use; `hacd scenario new | show | fields | set | fit | mechanisms | report` (v6.4) is the project workflow — the web pages' operations on a project file and its Findings report — over `packages/core/src/project/edit.ts`, also the operator tools `hacd_scenario_*` and the MCP tools `scenario_*` (`packages/mcp`). `npm test` also runs the CLI tests (the operate tests spawn the mock; about 2.5 min).
- `packages/reports` — the bilingual HTML report kit and the Findings / Methodology / BOM recipes as pure functions of the sidecar JSON (`results.json`, `mechanisms.json`, `provenance.json`, `records.json`, the studies; `bom.json`); `src/schematic.mjs` is the topology schematic shared with the web app; `src/index.mjs` is the Node entry (KaTeX fonts from the installed package via `katex-node.mjs`), `./browser` the same kit for a web worker, `./schematic` the drawing alone. `node packages/reports/test/reproduce.mjs` must print six OK after any change to a recipe or to `docs/backup/ascend-allocation`; after a recipe change regenerate the committed pages with `hacd findings --data docs/backup/ascend-allocation --out docs` (and `hacd bom --records native950,ubl128,cm384,a3server --out docs/ASCEND_BOM_100K.html --data-out docs/backup/ascend-allocation` when the BOM data changes). `docs/backup/pilots/` holds the committed evidence of the operator-protocol pilots (manifests, operator results, report sidecars; no pages, no internal data); `data-staging/` is the ignored working area of a pilot and never enters git.

## Rules
- Every number shown to a user carries its formula and its 口径 (event, denominator, level). Never add quantities of different event classes.
- First-order checkpoint formulas must check τ+δ ≪ M and R ≪ M and flag the regime.
- Non-exponential or correlated inputs route to Monte Carlo; the closed-form result is still shown with a delta badge.
- Parameters from the survey keep provenance and confidence (measured / paper-reported / vendor / derived / assumed / scan-level).
- A design is its mechanisms in their recorded order of application: a derated twin or a rebuild uses `applyMechanismsInOrder`, never the library order (`MODEL_REFERENCE.md` §22.4.1). The window rule needs at least `minWindowTrials()` windows (35 for P ≥ 0.9); formula (2) has no requirement when B ≤ 0 (`reachable` false) — print the reason, never a negative MTBF.
- Run `npm test` (goldens) before claiming a core change works; UI changes are checked at 1280 px and 375 px in light and dark.

## Model and effort routing for delegated work
Applies to Agent-tool sub-agents and to sessions started from a HAC-D session. Pick the model per session and keep it; never switch mid-session.
- Research lead, survey synthesis, parameter 口径 and confidence, allocation judgment: Fable 5.1 at high effort. Max only for the final reconciliation pass over a parameter set.
- Formula derivation under `packages/core`: Fable 5.1 at xhigh or max. Independent verifier (model-check): a fresh session on Opus 5.5 at xhigh when goldens exist; a fresh Fable 5.1 session at xhigh when the formula has no golden yet.
- Extraction from the survey corpus, grep over reports, citation counts: Sonnet 5.5 at low effort (Haiku 5.5 for pure grep). Workers return raw wording and location only; the lead assigns event class, denominator, level and confidence. A worker never decides what may be added to what.
- Report builds (`scripts/build-*.mjs`, bilingual HTML, SVG figures): Opus 5.5 at medium or high.
- UI code in `apps/web`: Opus 5.5 at high. Screenshot checks at 1280 px and 375 px, light and dark: Sonnet 5.5 at low.
- Delegate only when there is bulk to fan out (parallel report builds, corpus extraction). A single dependent chain, such as one formula change plus its golden check, stays in one session.
- Run sub-tasks at the lower setting and re-run only the failures higher; goldens, reference-compare and the review checklist are the checkers.
