# Update inputs (v6 ingest, maintainer side)

The internal side runs the chain with `hacd ingest run` (manifest `run.json`, exit 0 / 2 / 3) and its on-prem model follows `hacd ingest protocol` (`docs/markdown/AGENT_OPERATOR.md`); a batch arrives here as the staging folder plus `run.json`. Nothing internal reaches this side: work on the staged JSON / worksheets / extension requests you are given, or on synthetic fixtures (`hacd ingest template <kind>`). Plan: `docs/markdown/PLAN_V6_INPUT_MIGRATION.md`; formulas: `MODEL_REFERENCE.md` §26; commands: `USER_GUIDE.md` "v6 ingest".

1. **Stage.** Worksheets → records: `node --import tsx packages/cli/src/main.ts ingest worksheet <ws.md>… --out data-staging/<batch>`; device tables → override: `… ingest normalize --devices <device-fit.md> --mapping <koujing-mapping.md> --id <id> --out data-staging/<batch>`. A worksheet the loader rejects for an unknown template / unit / mechanism is written as an extension request, not an error.
2. **Gates.** `… ingest validate data-staging/<batch>` — errors block; read every warning: `implausible` (compare with the unit library and the mapping's impact factors), `provenance-missing`, `unknown-parameter`. Check the 口径 by hand once per batch: the override must be business-impact FIT per unit-hour (or per card with `basis: per-card`), never device FIT; classes hard / slow / sdc stay apart; `derived` entries carry their formula.
3. **Dry run and delta.** `… ingest dry-run --record <staged> [--rates <staged>] --scales 10000,100000 --trials 400`; then `… ingest diff --before-record <public or previous id> --after-record <staged> [--after-rates <staged>] --out data-staging/<batch>/delta` and read `delta.md` / `delta.html`: input changes with source and confidence, KPI rows before / after, Δ. A change the derivation does not explain is a finding, not a result.
4. **Promote** only into ids beside the public records (`native950`, `ubl128`, `cm384`, `a3server`, `a960e`, `remap-latest-2026-10`, `remap-per-card-2026-10-09` are never overwritten): `… ingest promote data-staging/<batch> [--data packages/core/data]`; then `npm test` and `node packages/reports/test/reproduce.mjs` (six OK — the public report set must not move).
5. **Extension requests** (`data-staging/<batch>/extension-requests/*.md`): a unit kind → unit-library entry + BOM row in `packages/core/src/topology/index.ts` (and its catalog events); a template → `TOPOLOGY_TEMPLATES` entry + the records round trip; a mechanism → `MechanismDef` with `apply`, `parameters`, `reads`, effort, through the `model-check` skill (independent derivation, golden). Routing per CLAUDE.md: formula work Fable 5.1 at xhigh, verifier a fresh session.
6. **Pipeline changes** (worksheet profile, gates, normaliser): keep `hacd schema --record|--mechanisms|--rates` and the worksheet templates in step; round-trip tests (`packages/importers/test/worksheet.test.ts`), `test/ingest_v6.test.ts`, the Python golden `compute_golden_v6.py` (never edit expected values by hand); rebuild the offline bundle `node scripts/bundle-offline.mjs` and check it from an empty folder with `HACD_DATA` set.
